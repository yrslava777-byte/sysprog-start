# Проверки

Здесь лежит программа, которая проверяет работы: [`run_checks.py`](run_checks.py).
GitHub Actions запускает её после каждой отправки кода сразу на трёх серверах —
с Windows, macOS и Linux. Результат: вкладка **Actions** → **Проверки** → последний запуск → **Summary**.

Что проверяется:

| Что | Как |
|---|---|
| лабораторные с кодом | программа собирается компилятором системы и печатает ожидаемую строку |
| агент-сторож | 13 проверок; каждая открывается на своей паре, до этого отмечена «ещё не открыта» |

Открытые проверки агента:

| № | Пара | Проверка | Как |
|---|---|---|---|
| 1 | 4 | Список процессов совпадает с системным | ядро собирается из `agent/core/*.c`; `core_list_procs` при `max = 1` возвращает код нехватки места и нужное число, а с запасом — список, в котором есть сама проверка с верным родителем; список сверяется с `ps` (в Windows — `Win32_Process`): пропущенных и лишних процессов не больше 5 или 10%, у 95% общих совпадает родитель |

Код лабораторной пишется для своей системы. Сервер с другой системой его пропускает:
`hello.c` с `windows.h` собирается только на Windows, с `unistd.h` — только на macOS и Linux.

Запустить проверку на своём компьютере:

```bash
python checks/run_checks.py        # macOS и Linux: python3
```

В Windows команду нужно выполнять в **x64 Native Tools Command Prompt for VS**, иначе компилятор `cl` не найдётся.

Папку ведёт преподаватель: при обновлении материалов файлы в ней заменяются.
