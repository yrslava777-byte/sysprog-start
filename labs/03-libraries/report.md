# ЛР 3. Библиотеки программы

Система: macOS 26.6.2, Apple Silicon (arm64). Работа выполнена в VS Code, компилятор clang, Python 3.9.6 из Command Line Tools.

## Библиотеки файла

Программа напечатала: `./libs: sqrt(2) = 1.414214`.

Команда для списка библиотек файла: `otool -L libs`.

Библиотеки libs: одна — `/usr/lib/libSystem.B.dylib` (compatibility version 1.0.0, current version 1356.0.0).

Почему в списке нет отдельной математической библиотеки (или почему она есть): в macOS стандартная библиотека C, математические функции и системные вызовы предоставляются через libSystem. Отдельного подключения libm ключом `-lm`, как в Linux, не требуется; программа динамически связана с libSystem.

Где лежит интерпретатор Python (файл или библиотека): исполняемый файл `/Library/Developer/CommandLineTools/usr/bin/python3` — обёртка, которая использует библиотеку `@executable_path/../Python3`, то есть `/Library/Developer/CommandLineTools/usr/Python3`. В ней находится интерпретатор. Команда `otool -L "$(python3 -c 'import sys; print(sys.executable)')"` показала зависимости `Python3` и `/usr/lib/libSystem.B.dylib` для двух архитектур — x86_64 и arm64, поскольку файл универсальный.

## Библиотеки процесса

PID Python: 92820 (результат `os.getpid()` в интерактивном Python).

Библиотек в процессе до ctypes.CDLL: 172, после: 174. Подсчёт выполнен в соседнем терминале для того же процесса:

```sh
P=92820
vmmap $P | grep -o '/[^ ]*\.dylib' | sort -u | wc -l
vmmap $P | grep -o '/[^ ]*pcap[^ ]*' | sort -u
```

До загрузки поиск `pcap` ничего не вывел. После загрузки найдена библиотека по полному пути `/usr/lib/libpcap.A.dylib`. Короткое имя при загрузке — `libpcap.dylib`.

Функция вернула: `b'libpcap version 1.10.1'`.

В работающем Python последовательно выполнены команды:

```python
import ctypes
lib = ctypes.CDLL("libpcap.dylib")
lib.pcap_lib_version.restype = ctypes.c_char_p
lib.pcap_lib_version()
```

`restype = ctypes.c_char_p` задаёт возвращаемый тип — указатель на строку C, которую ctypes преобразует в байты Python. Сравнение карт памяти до `import ctypes` и после вызова функции показало две новые библиотеки: `/usr/lib/libffi.dylib` и `/usr/lib/libpcap.A.dylib`. libffi нужна ctypes для вызова функций C. Python не перезапускался, PID остался тем же.

## Помощник ИИ (Р1)

Запрос: «Чем статическая компоновка отличается от динамической?». Совпал ли ответ с таблицей §2: да. При статической компоновке нужный код библиотеки включается в исполняемый файл, поэтому обновление этого кода требует пересборки программы. При динамической компоновке программа использует отдельную библиотеку, которую загружает система; исполняемый файл обычно меньше, но зависит от наличия совместимой библиотеки. Загрузка через ctypes.CDLL выполняется уже во время работы процесса, когда библиотека понадобилась.

Не получилось: при дополнительном сохранении карты памяти из ограниченной среды команда vmmap сначала сообщила о недостаточных правах. Сохранение повторено вне ограниченной среды для собственного учебного процесса; в терминале VS Code обе проверки выполнились. Все шаги лабораторной завершены.
