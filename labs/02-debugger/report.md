# ЛР 2. Программа в отладчике

Система: macOS 26.6.2, Apple Silicon (arm64) · отладчик: LLDB, запуск из VS Code с расширением Microsoft C/C++.

## Остановка и переменные

Программа без отладчика напечатала: `agent: total=6 area=12`.

Точка останова на строке 15.

До строки 15: p.x = -16, p.y = -1, total = 1.

После строки 15: p.x = 3, p.y = 4.

Строку 16 отладчик пропустил, потому что объявление `char name[8];` без инициализации не создаёт отдельной исполняемой команды: место под массив уже выделено в стеке при входе в функцию.

name[0] = 97 (код буквы `a`), завершающий ноль в ячейке name[5]. Первые шесть байтов после `strcpy`: 97, 103, 101, 110, 116, 0. Ячейки name[6] и name[7] функция `strcpy` не заполняет.

## Цикл и функция

На кадре цикла: i = 2, total = 1; после следующего шага total = 3. Значения наблюдались в Watch перед выполнением строки 21 и после неё.

В стеке внутри area строк: 3, сверху функция area. Два кадра относятся к исходному коду: `area` (debug.c:10) и `main` (debug.c:22); третий — системная функция `start` из dyld.

Команда умножения в машинном коде: `mul w8, w8, w9` (ARM64). Перед ней команды `ldr` загружают поля структуры в регистры, после неё `str` сохраняет результат в `s`.

Перед printf: a = 12, total = 6.

Под отладчиком программа напечатала: `agent: total=6 area=12`.

Код завершения программы: 0 (`0x00000000`), подтверждён в Debug Console.

## Помощник ИИ (Р1)

Запрос: «Почему до выполнения строки 15 в p.x лежит случайное число?». Совпал ли ответ с шагом 4: да. Память под локальные переменные выделена, но инициализация структуры ещё не выполнена. Отладчик показывает оставшиеся в этой памяти байты. До инициализации значение не определено, полагаться на него в программе нельзя; при другом запуске показания могут измениться. Строка 15 записывает в поля структуры значения 3 и 4.

Не получилось: при первом запуске LLDB возникла ошибка `attach failed`, поскольку режим разработчика macOS был выключен. После включения с разрешения пользователя отладка выполнилась: точка останова, шаги, просмотр массива, Watch, вход и выход из функции, стек вызовов и Disassembly.

ИИ: использовал для подготовки файлов по образцу, настройки и выполнения отладки, объяснения неинициализированной памяти и оформления отчёта по фактическим наблюдениям.
